# Investments V2 — Cash Reconciliation Demo Walkthrough

**Audience:** Client presentation / documentary judge (M.G.)  
**Purpose:** Guide a live demo of the reconciliation journey from portfolio overview through fund cash matching, ledger review, exception resolution, and outgoing client statements.

**Entry point:** Sign in → **Investments V2** → **Reconciliation**

---

## The story in one minute

Cash reconciliation follows a controlled path:

```text
Overview (where are we?) 
  → Fund cash (import bank file → validate → approve → match)
  → Cash ledger (posted movements)
  → Exceptions (breaks needing analyst decision)
  → Client statements (outgoing reports to investors)
```

> **Important distinction:** **Incoming** bank/custodian statement files (Fund cash → Import Statements) are not the same as **outgoing** client cash statements (Statements tab). Both live under Reconciliation, but they serve different purposes.

---

## Display labels (what “good” looks like)

Throughout the demo, the UI should show **human-readable labels**, not internal system identifiers:

| Field | Good | Gap (call out if seen) |
| --- | --- | --- |
| Account number | e.g. `ACC-014-USD` | `—` or a long opaque id |
| Client name | e.g. `Acme Pension Fund` | `—` |
| Cash account (dropdown / table) | Account number + client or fund name | Raw id only |
| Fund / portfolio | Fund name | Id string |
| Generated by (statements) | Person or system name | `—` or id |
| Assigned to / approver (exceptions) | Analyst name | `—` |

If a column shows **—**, treat it as a **data enrichment gap** (the screen is working; the backing record lacks a display name). Do not interpret an em dash as “no data” unless the whole table is empty.

## Flow 1 — Client Accounts Overview

**Route:** `/investments-v2/reconciliation`

### Why this screen

This is the **reconciliation cockpit**. Before matching bank lines or resolving breaks, operations and client-facing teams need a single view of client cash positions, open items, and recent exception activity across accounts.

### What you should see

**Page title:** *Client Accounts Overview*  
**Subtitle:** *Real-time summary of client cash positions, activity and exceptions.*

**Toolbar**

| Control | Purpose |
| --- | --- |
| Search | Filter by account number or client name |
| As-of date | Snapshot date for movement chart and totals |

**KPI cards (top row)**

| KPI | Meaning |
| --- | --- |
| Total Client Cash | Aggregate cash across client accounts (primary currency + secondary if applicable) |
| Available Cash | Cash eligible for orders / unrestricted use |
| Pending Settlements | Amount held in active reservations |
| Unreconciled Items | Count of open breaks on accounts |
| Exceptions | Count of unhealthy accounts flagged for attention |

**Client Accounts table**

| Column | What to point at |
| --- | --- |
| Account Number | Human-readable account code (linked style) |
| Client Name | Legal or display client name |
| Base Currency | USD, ZWL, etc. |
| Account Type | Custody, trading, etc. |
| Cash Balance | Total balance |
| Available Balance | After holds |
| Status | Active or Restricted badge |
| Last Activity | Most recent movement date |

**Filters:** Account type, Status (Active / Restricted), pagination.

**Bottom panels (three columns)**

| Panel | Content |
| --- | --- |
| Cash by Currency | Donut chart + currency breakdown with amounts |
| Daily Cash Movement (USD) | Net movement and closing balance trend lines |
| Recent Alerts & Exceptions | Top open items with account · client, amount, age — link **View all** goes to Exceptions |

### Actions and outcomes

| Action | Expected result |
| --- | --- |
| Search / filter accounts | Table refreshes to matching rows |
| Change as-of date | KPIs and daily movement chart update |
| Click **View all** (exceptions panel) | Navigate to `/investments-v2/reconciliation/exceptions` |
| Select **Fund cash** tab | Proceed to Flow 2 |

### Good vs empty / error

| State | What it looks like | How to present |
| --- | --- | --- |
| **Good** | KPIs show currency amounts; table has rows with account numbers and client names; chart has data points | “This is our daily control tower — cash, breaks, and alerts in one place.” |
| **Empty table** | “No client cash accounts found.” | No accounts in scope for this environment — not a UI failure. |
| **Empty chart** | “No daily movement data returned.” | No movement history for the selected date — KPIs may still populate. |
| **Empty alerts** | “No recent exceptions.” | Clean book — optionally note exceptions may still exist on the Exceptions screen. |
| **Error banner** | “Unable to load cash overview” / accounts error | Service unavailable — pause demo on this screen. |
| **Label gap** | Client Name or Account Number shows **—** | Call out enrichment gap; do not show raw ids to the client. |

## Flow 2 — Fund Cash Reconciliation

**Route:** `/investments-v2/reconciliation/fund-cash`

### Why this screen

This is where **fund cash** is reconciled: internal ledger entries are matched to **external bank/custodian statement lines**. The screen supports controlled file ingestion (maker/checker), batch-scoped matching, and break analysis.

### What you should see

**Page title:** *Fund Cash Reconciliation*  
**Subtitle:** *Reconcile internal fund cash ledger against bank and custodian statements.*

**Header actions**

| Button | Role |
| --- | --- |
| Reconciliation Rules | View active matching rules |
| Import Statements | Open external file ingestion modal |
| New batch | Create a reconciliation batch for an account / period |

**Batch toolbar**

| Control | Purpose |
| --- | --- |
| Fund | Filter batches by fund |
| Batch | Select scoped batch (account, currency, period in label) |
| Scope (cash account) | Narrow to one cash account |
| As At | Period end date |
| Auto-match toggle | Enable automatic matching on run |
| Run Reconciliation | Execute matching for selected batch |
| Status chips | **Balanced** / **Fully reconciled** + batch status + last run time |

**KPI row**

| KPI | Meaning |
| --- | --- |
| Fund | Fund name and total cash |
| Open Breaks | Count of unresolved breaks |
| Unreconciled Value | Monetary variance on open breaks |
| Unmatched Items | Lines still without a pair |
| Reconciled % (Value) | Match rate by value |

**Three-column workspace**

| Column | Title | Columns |
| --- | --- | --- |
| 1 | Internal Fund Cash Entries | Date, Description, Amount |
| 2 | Bank Statement Lines | Date, Description, Amount |
| 3 | Matched Results / Break Analysis | Tabs: **Matched**, **Breaks**, **Unmatched** — table: Date, Type, Details, Amount |

**Side panel (when a break row is selected):** Break details, comment field, **Confirm manual match**, **Unmatch (reversal)**, **Mark as Reviewed**.

**Lower panels**

| Panel | Content |
| --- | --- |
| Matching Suggestions | Pairs with confidence %, band label, score breakdown (Amount · Date · Ref · Counterparty), **Confirm** button |
| Reconciliation Rules (Active) | Rule names and modes |

**Suggestion confidence bands**

| Band | Score | Meaning |
| --- | --- | --- |
| Auto-match eligible | ≥ 95% | High confidence — safe to confirm |
| Suggested | 85–95% | Review then confirm |
| Weak (investigate) | 65–85% | Needs analyst judgment |
| Below threshold / Hard rule blocked | < 65% or rule fail | Cannot auto-confirm |

---

### Part A — External statement ingestion

Open **Import Statements** → modal **External statement ingestion**.

**Status stepper:** `RECEIVED` → `VALIDATED` → `PENDING_APPROVAL` → `COMMITTED` (plus `REJECTED` if declined)

**Setup fields**

| Field | What to select |
| --- | --- |
| Cash account | Account from dropdown (should show readable label) |
| Provider | Bank/custodian feed (e.g. CBZ Custody) |
| Currency | USD or account currency |
| Control opening / Control closing | Statement opening and closing balances (required before commit) |

**Demo file templates** (download pills in modal): Happy path, Breaks demo, Validation fail, Debit/credit columns.

#### Step-by-step demo path

| Step | Action | What you should see | Talking point |
| --- | --- | --- | --- |
| 1 Upload | Select a CSV in the drop zone | Status **RECEIVED**; file name; SHA-256 hash; import reference | “File is staged only — nothing posted yet.” |
| 2 Validate | Click **Validate** | Status **VALIDATED**; control totals panel (Opening · Movements · Closing); **balanced** indicator | “Schema and control totals checked before approval.” |
| 3 Submit | Click **Submit for approval** | Status **PENDING_APPROVAL** | “Maker submits; checker will commit — four-eyes control.” |
| 4 Commit | Confirm opening/closing filled → **Commit** | Status **COMMITTED**; modal closes; success message; bank lines available for matching | “Immutable external lines are now available for reconciliation.” |

**Optional beats (short)**

| Beat | Action | Outcome |
| --- | --- | --- |
| Validation failure | Upload validation-fail template → Validate | Line/field error list; Submit and Commit disabled | “Bad files never reach the ledger.” |
| Duplicate file | Re-upload same file after commit | Duplicate-source error | “Hash identity prevents double posting.” |
| Reject | Enter reject reason → **Reject batch** | Import rejected; no ledger impact | “Checker can decline before commit.” |

---

### Part B — Reconciliation batch and matching

| Step | Action | What you should see |
| --- | --- | --- |
| 1 Create batch | **New batch** → cash account, currency, period from/to → **Create batch** | Batch appears in picker; workspace loads internal and bank lines |
| 2 Run | **Run Reconciliation** | Suggestions panel fills; Matched / Breaks / Unmatched counts update; **Last run** timestamp |
| 3 Confirm suggestion | Pick **Suggested** or **Auto-match eligible** → **Confirm** | Row moves to **Matched** tab; unmatched count drops |
| 4 Manual match | Select one internal line + one bank line → **Confirm manual match** | New match with non-zero amount |
| 5 Unmatch (optional) | Enter unmatch reason → **Unmatch (reversal)** | Lines return to unmatched; audit retained |

**Batch status labels**

| Label | Meaning |
| --- | --- |
| **Balanced** | Control totals align (open items may remain) |
| **Fully reconciled** | Balanced **and** no open breaks or unmatched lines |

### Good vs empty / error (Fund cash)

| State | What it looks like | How to present |
| --- | --- | --- |
| **Good** | Batch selected; internal and bank panes populated; after run, suggestions with confidence bars; Matched tab has rows | Full recon story demonstrated |
| **No batch** | Batch dropdown “No batch”; empty workspace | Create a batch or select an existing one |
| **No suggestions** | “No suggestions.” after run | All lines matched manually, or no overlapping period |
| **No entries** | “No entries.” in internal or bank pane | Import not committed, or wrong account/period |
| **Import blocked** | Red error text; Submit/Commit greyed out | Validation or control totals — fix inputs and re-validate |
| **Label gap** | Cash account dropdown shows id only | Enrichment gap — should show account number + client |

## Flow 3 — Cash Ledger

**Route:** `/investments-v2/reconciliation/cash-ledger`

### Why this screen

After reconciliation and posting, finance needs an **auditable cash ledger**: every debit, credit, and running balance for fund operations and client trading cash. This confirms that matched activity appears as ledger lines with approval status.

### What you should see

**Segment toggle:** **Fund** | **Trading**

| View | Title | Subtitle focus |
| --- | --- | --- |
| Fund | Fund Cash Ledger | Cash movements and balances across funds |
| Trading | Trading Cash Ledger | Client trading cash, settlements, available balances |

**Filters:** Fund / Portfolio, Valuation date, Currency (All, USD, ZWL, ZWG)

**KPI cards**

| Fund view | Trading view |
| --- | --- |
| Total Fund Cash | Total Client Cash |
| Unrestricted Cash | Available to Trade |
| Open Break Variance | Active Reservations |
| Ledger Rows (count + page) | Ledger Rows |
| View: Fund | View: Trading |

**Ledger table — Fund columns**

Date · Fund · Cash Account · Bank · Transaction Type · Description · Debit (USD) · Credit (USD) · Running Balance (USD) · Currency · Approval Status

**Ledger table — Trading columns**

Date · Client · Account · Cash Account · Bank · Transaction Type · Description · Debit · Credit · Running Balance · Currency · Approval Status

**Fund-only extras:** Sub-tabs (Ledger, Capital Calls, Distributions, Fees, Documents — non-Ledger tabs link to other modules); **Daily Cash Movement (USD)** chart below the table.

### Actions and outcomes

| Action | Expected result |
| --- | --- |
| Switch Fund ↔ Trading | Different KPIs and column set; ledger lines filtered by purpose |
| Filter by fund / currency / date | Table and totals refresh |
| Paginate | “Showing X to Y of Z transactions” |

### Good vs empty / error

| State | What it looks like | How to present |
| --- | --- | --- |
| **Good — Fund** | Multiple rows with fund name, cash account label, debits/credits, running balance | “Fund-level cash posted from recon and operations.” |
| **Good — Trading** | Rows with **Client**, **Account** (number), transaction types (settlement, fee, etc.) | “Client trading cash — what the client sees on statements.” |
| **Empty** | “No ledger entries for this segment.” | Wrong segment or date filter — try Trading vs Fund or widen date |
| **Error** | “Unable to load ledger.” | Service issue |
| **Label gap** | Client, Account, or Cash Account shows **—** | Enrichment gap — names should resolve from master data |

## Flow 4 — Exceptions & Approvals

**Route:** `/investments-v2/reconciliation/exceptions`

### Why this screen

Not every break auto-clears. Material variances escalate to **exceptions** requiring investigation, documentation, and an approval decision (adjust, reject, or request more information).

### What you should see

**Page title:** *Reconciliation Exceptions & Approvals*

**Summary KPIs**

| KPI | Meaning |
| --- | --- |
| Critical / High | Count and USD value of severe items |
| Overdue Approvals | Items past SLA |
| Pending Adjustments | Awaiting decision (with investigating count) |
| Straight-Through Match Rate | Auto-match success from summary |

**Filters:** Severity (Critical → Low), Status (Pending Approval, Investigating, Overdue)

**Exceptions table**

| Column | Content |
| --- | --- |
| Severity | Critical / High / Medium / Low badge |
| Account | Account number (readable) |
| Client | Client name |
| Source | Where the break originated |
| Exception Reason | Short description |
| Amount Difference | USD and ZWL variance |
| Age | Days open |
| Assigned To | Analyst name |
| Status | Pending Approval, Investigating, Overdue, Resolved, Closed, Rejected |

**Detail panel (select a row)**

- Header: severity + status badges, title, account · client, amount difference  
- Context grid: Source, Portfolio, Custodian, Instrument, Quantity, Trade/Settle dates, Assigned To, Approver  
- Tabs: **Timeline**, **Comments**, **Attachments**, **Audit Trail**  
- **Approval Actions:** Approve & Adjust · Request More Info · Reject  
- Notes field + **Submit Decision**

### Actions and outcomes

| Action | Expected result |
| --- | --- |
| Filter by Investigating | List shows open items under review |
| Select exception | Detail panel loads timeline and metadata |
| Post comment / attach file | Collaboration recorded on exception |
| Choose decision + **Submit Decision** | Status updates; list refreshes; open KPI counts drop when closed |

### Good vs empty / error

| State | What it looks like | How to present |
| --- | --- | --- |
| **Good** | Mix of severities; Account and Client columns populated; detail timeline has events | “Analyst workflow with full audit trail.” |
| **Resolved demo** | Approve or Reject with notes → status becomes Resolved / Rejected | “Four-eyes and documented closure.” |
| **Empty list** | “No exceptions found.” | Clean recon — or adjust filters |
| **No selection** | “Select an exception to review.” | Click a table row |
| **Label gap** | Account, Client, Assigned To, or Approver shows **—** | Enrichment gap |

## Flow 5 — Client Statements

**Route:** `/investments-v2/reconciliation/statements`

### Why this screen

This is **outgoing** reporting: periodic **client cash statements** generated from the trading cash ledger, reviewed, approved, and delivered (PDF / email). It is separate from the bank files imported on Fund cash.

### What you should see

**Page title:** *Client Statements* (segment: **Client** | **Investor**)

For this recon demo, stay on **Client** segment.

**Subtitle:** *Generate and deliver client cash statements from the trading cash ledger.*

**Filters:** Account, Currency, Status (Draft, Pending Approval, Approved, Delivered)

**KPI row (Client segment)**

| KPI | Meaning |
| --- | --- |
| Client Cash Covered | Total cash in scope |
| Accounts in Scope | Number of accounts with statement runs |
| Period Movements | Net movement in period |
| Pending Delivery | Draft + pending approval count |
| Statements Ready | Ready count vs total with progress bar |

**Statement Schedule & History table**

| Column | Content |
| --- | --- |
| Period | e.g. Jul 2026 |
| As At Date | Statement date |
| Account | Cash account label (number + name) |
| Status | Draft, Pending Approval, Approved, Delivered |
| Clients | Client count or name |
| Generated By | User or system name (**not** an internal id) |
| Generated On | Timestamp |

**Preview panel (right)**

Action bar: **Generate Batch** · **Preview** · **Approve** · **Email** · **Download PDF**

When a run is selected, preview shows:

- Letterhead (*Zambezi Asset Management* — Client Cash Statement)  
- Client / Account block with client name and account number  
- Statement period and status  
- **Cash Movement Summary** — Opening Cash, line items, Closing Cash  

### Actions and outcomes

| Action | Expected result |
| --- | --- |
| Select statement run | Preview loads in right panel |
| **Preview** | HTML preview or summary panel refreshes |
| **Approve** (Draft / Pending) | Status moves toward Approved |
| **Download PDF** | PDF file downloads |
| **Generate Batch** | New statement run created for current filters / period |
| **Email** | Delivery initiated (when configured) |

> **Demo note:** Excel/CSV export is not part of this screen — PDF is the primary deliverable.

### Good vs empty / error

| State | What it looks like | How to present |
| --- | --- | --- |
| **Good** | Table has runs; Account and Generated By are readable; preview shows client name, movements, opening/closing | “Client-ready statement from reconciled ledger data.” |
| **Approved path** | Draft → Preview → Approve → Download PDF | Full governance loop |
| **Empty** | “No client statements for this segment.” | Generate a batch or widen filters |
| **Preview placeholder** | “Select a statement run to preview.” | Click a row in the schedule table |
| **Error** | “Unable to load statements.” / “Preview failed” | Service or missing statement content |
| **Label gap** | Generated By, Clients, or Account shows **—** | Enrichment gap — should show names |

**Investor segment:** Available for LP capital statements; capital line detail may be limited compared to client cash. For a focused recon demo, remain on **Client**.

## Talking points (quick reference)

| Moment | What to say |
| --- | --- |
| Overview | “Single cockpit for cash, breaks, and alerts before we drill into matching.” |
| Import RECEIVED | “Staged only — file identity via hash; no ledger impact yet.” |
| Validate | “Structure and control totals before anyone can approve.” |
| Submit vs Commit | “Maker submits; checker commits — segregation of duties.” |
| Run Reconciliation | “Confidence is explained — amount, date, reference, counterparty.” |
| Balanced vs Fully reconciled | “Balanced means totals tie; fully reconciled means nothing left open.” |
| Cash ledger | “Posted movements with approval status — audit trail after recon.” |
| Exceptions | “Material breaks get an owned workflow, not a spreadsheet.” |
| Statements | “Outgoing client report — not the bank file we imported earlier.” |
| Em dash (—) | “Missing display label — enrichment item, not a broken screen.” |
