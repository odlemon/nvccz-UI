# Recon — display labels + statement PDF (backend asks)

**Date:** 2026-07-21  
**Product rule:** Operators must never see Prisma/cuid database ids in recon tables or alert widgets. Client statement download must produce an openable PDF.

**FE mitigation (shipped):** Adapters hide opaque ids (`displayLabel` / `isOpaqueId`), and pages resolve `cashAccountId` → account number via `GET /client-cash-accounts`. Statement download uses `responseType: 'blob'` + `%PDF` magic-byte / base64 JSON fallback.

---

## BA-R7 — Human labels on list payloads

### Why
Exceptions, cash ledger, recent alerts, and client statements currently omit join fields. FE falls back to resolving accounts client-side (extra round trip) and shows `—` for users when name fields are missing.

### Endpoints
| Method | Path | Add fields |
| --- | --- | --- |
| `GET` | `/api/investment-ops/cash-exceptions` (or exceptions list used by FE) | `accountNumber` / `accountNumberMasked`, `cashAccountLabel`, `clientName` |
| `GET` | `/api/investment-ops/cash-ledger` | `cashAccountName` or `accountNumber`, `clientName`, `fundName` |
| `GET` | `/api/investment-ops/client-statements` | `generatedByName` (or nested `{ id, name, email }`), never raw `approvedById` as the display field |

### Example exception item (desired)
```json
{
  "id": "cexc_…",
  "cashAccountId": "cmrsujspx008tunlofkog32jx",
  "accountNumber": "ZAM-001-001",
  "accountNumberMasked": "ZAM***001",
  "cashAccountLabel": "ZAM-001-001",
  "clientName": "Acme Pensions",
  "category": "MISSING",
  "amountDifference": "75.00"
}
```

### Example statement item (desired)
```json
{
  "id": "ccst_…",
  "generatedByName": "Admin User",
  "generatedByEmail": "admin@nts.com",
  "approvedByName": "Admin User"
}
```

### Error / verify
- No change to error codes.
- **FE verify:** Account / Cash Account / Generated By / Recent Alerts meta show numbers or names, never `cmr…` cuids.
- **FE consumers:** `cash-recon-adapter.ts`, `reconciliation/page.tsx`, `exceptions/page.tsx`, `cash-ledger/page.tsx`, `statements/page.tsx`.

## BA-5 / BA-R8 — Statement PDF download (binary)

### Why
`GET …/client-statements/:id/download` with `Accept: application/pdf` must stream real PDF bytes. If FE JSON-parses the body, the saved file is corrupted and will not open.

### Contract
Prefer binary:

```
HTTP/1.1 200
Content-Type: application/pdf
Content-Disposition: attachment; filename="statement-….pdf"

%PDF-1.4 …
```

Or JSON envelope (still supported by FE):

```json
{
  "success": true,
  "data": {
    "fileName": "statement.pdf",
    "contentBase64": "<base64 of PDF bytes starting with JVBERi0…>"
  }
}
```

### Verify
1. Download from Client Statements → file opens in a PDF reader.
2. First bytes are `%PDF` (not `{` JSON).
3. FE files: `stock-picker-cash-api.ts` (`downloadClientStatement` + `responseType: 'blob'`), `statements/page.tsx` `downloadSelected`.
